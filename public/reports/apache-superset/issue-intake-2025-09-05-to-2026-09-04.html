How Devin usage is charged

Devin does not publish one universal hourly rate. Cost depends on account type and the model work performed.

  • Self-serve: paid plans include daily and weekly usage allowances. Extra usage is consumed at API token pricing; included quota can reduce incremental cash cost.
  • Enterprise: newer contracts meter Agent Compute Units (ACUs). Dollar cost is ACUs × contracted $/ACU; no public universal enterprise ACU price is available.
  • Runtime: planning, tool use, browser/code execution, VM, and networking contribute to usage. Sessions generally consume little while waiting and sleep when idle, so elapsed issue age is not billable runtime.
  • Plan fees: public list prices start at $20/month Pro, $200/month Max, or $80/month for Teams plus $40/month per full seat. These are separate from the extra-usage estimate.
Not used: the documented Adaptive promotional token rate ended 7 July 2026, and SWE-1.7’s free preview ended 8 August. Neither expired promotion is treated as the current price.

Methodology

Definitions, sources, and limits

Scope

Public issues opened in apache/superset from 2025-09-05 00:00 UTC through 2026-09-04 23:59 UTC. Pull requests are excluded. The window uses 365 complete days so an incomplete collection day does not distort intake.

Collection

GitHub REST search identified the monthly cohorts. Each issue’s public comments and timeline events were collected on 2026-09-05. Query pattern: repo:apache/superset is:issue created:YYYY-MM-DD..YYYY-MM-DD.

Bug report

An issue is counted as a bug when it has a #bug-family label or retains at least two recognizable fields from Superset’s official bug form (for example Bug description, reproduction steps, screenshots, expected behavior, or Superset version). This catches reports whose generic #bug label was later replaced by a more specific label.

Clarification

A public non-reporter comment explicitly asks for evidence such as versions, steps, logs, screenshots, configuration, sample data, or more information, or a more-info/missing-reproduction label is applied. Bot and human requests are separated; one issue can contain both.

Reproduction proxy

GitHub has no authoritative reproduction timestamp. The report counts an explicit successful reproduction/verification statement or a validated/regression label. Negative “cannot reproduce” language is excluded. The proxy is intentionally conservative and likely undercounts private, implicit, or code-only reproduction.

Back-and-forth proxy

The strict cycle requires three public events in order: a human clarification request, a later reporter reply, and a later reproduction signal. Only 8 reports met this observable sequence, so its timing is shown as directional evidence rather than a service-level metric.

Resolution

“Closed” and GitHub’s completed/not-planned/duplicate reasons are direct metadata. “Fix/PR signal” is a stricter but imperfect proxy: the issue is closed and has a PR cross-reference, explicit maintainer fix/merge wording, or closes-issue label. A cross-reference does not prove merge or causality.

Response

A maintainer response is the first comment whose GitHub author association is OWNER, MEMBER, or COLLABORATOR. Community answers and automated bot comments are not counted as maintainer responses.

Important limitations

  • Deleted comments, private discussions, Slack, and internal tracking are invisible.
  • Current labels may differ from labels at intake; timeline events recover some but not all history.
  • Text detection can produce false positives or miss paraphrases.
  • Issues near the end of the cohort have less time to close than early issues.
  • Closure rate is a cohort snapshot, not a causal measure of maintainer performance.

Capacity estimate

The Devin comparison is a separate scenario model layered onto the observed cohort. It does not infer labor hours from issue elapsed time. The 429 strict fix/PR proxy is used as the reviewable-PR workload; low/base/high handling times are explicit assumptions. FTE conversion uses 2,000 engineering hours per year. ACU planning assumes 0.5/1/2 ACUs per intake, 0.25/0.5/1 per clarification, and 6/12/25 per PR path. Token and ACU estimates are planning ranges, not invoices.
